## Content rules

- **English is the main language.** Korean appears only in the Teaching overview's course descriptions and in the short Korean summary at the end of a blog post (for busy Korean readers).
- **Public contact details only:** the lab address, the office phone, and the JBNU email address, as already set in `_config.yml`, `_pages/about.md`, and `_data/socials.yml`. Never add a mobile number or a personal email address. Do not copy contact details into other files, including this one.
- **Publications list (`papers.bib`):** published and in-press papers only, never papers under review or in revision. This rule applies to the publication list only (owner's decision, 2026-10-17). Other pages, such as Research, may cite manuscripts under review or in revision, marked "(in revision)" or "(under review)" with no DOI; currently the Kim and Kim wetlands paper (*Journal of Hydrology*, in revision). Add such a paper to `papers.bib` once it is accepted. Mark in-press papers with `note = {In press}`. Journal articles carry a verified DOI; the owner's name (`Kim, D.`) is highlighted through `scholar.last_name`/`first_name` in `_config.yml`. A co-author with the same surname and initial is written with a full given name (for example `Kim, Doyoung`) so that only the owner is highlighted.
- **People:** names, roles, and degrees only; never students' email addresses or photos. Everyone listed on the lab's previous site (hydroclimatol.com) was approved for listing by the owner on 2026-10-16; ask the owner before adding anyone else.
- **No placeholder text** such as "[Placeholder]" or "coming soon" lists. If information is missing, leave the item out. The single exception is "Online textbook — coming soon" on course pages, which is intentional.
- **No copyrighted third-party material:** no figures from papers, publisher images, or abstracts copied from publishers. Use the owner's own figures and photos. Publication thumbnails are the owner's own graphical abstracts (see Publications above). If a published figure is ever used instead, it must come from an open-access article under a Creative Commons licence, as one whole figure, only resized, with a credit line (`preview_figure`, `preview_license`).
- **No large files in the repository** (slides, videos, datasets such as netCDF). Link them from Google Drive. `.gitignore` blocks common large formats.
- Google Scholar and ORCID links stay commented out in `_data/socials.yml` until the owner provides them.

## Blog post style guide

Every post in `_posts/` follows the same structure, so that fonts and sizes stay consistent. Typography comes only from the site CSS (`_sass/_site.scss`); never put font sizes, fonts or colours in a post.

- **Front matter:** `layout: post`, `title`, `date` (with `+0900`), `description`, space-separated `tags`, `categories: paper-highlights` or `notes`, `related_posts: false`.
- **Body:** paragraphs and `##` section headings only (no `#`, and `###` only if truly needed). Emphasis with `**bold**` and `_italic_`.
- **Figures:** `![alt text](/assets/img/blog/<date>-<name>.png){: style="width: 100%; height: auto;" data-zoomable="" }` on its own line, then a caption paragraph written exactly as `_**Figure N.** Caption text. Figure by Daeha Kim, ..._` (`**Figure.**` when the post has a single figure). The caption is one italic paragraph that starts with bold; the CSS shows only this pattern smaller (14.4px vs 16px body).
- **"Questions to think about":** a bold paragraph `**Questions to think about**` followed by a numbered list.
- **Korean summary:** after a `---` rule, one paragraph starting `**한 줄 요약 (Korean summary).**`. No other Korean in a post.
- **References:** after a `---` rule, a bold paragraph `**References**` (or `**Reference**` for one), then one paragraph per reference in the same APA-like format: authors (year). Title. _Journal_, volume, pages or article number. If a DOI exists, end with the link written as `[https://doi.org/...](https://doi.org/...)`. Do not use lists for references.
- **Closing line:** one italic paragraph crediting the figures, linking each script on GitHub (`scripts/blog/<date>-<name>.py`).
- **Links between posts:** `{% post_url YYYY-MM-DD-slug %}`.
- **Math and dollar signs:** MathJax runs on every page with `$…$` as inline math (`al_math`, `enable_math: true`). Write equations as `$$…$$`. Two dollar amounts in one paragraph ("$41 … $39") otherwise turn into a garbled equation that widens the page on phones: in the body write `\\$41` (rendered as "$41"), and keep `$` out of `description` (shown on the Blog page); a single `$` in the title is safe.
- **Check:** after building, verify at 390px that body text, reference entries and the Korean summary share one size, and only figure captions are smaller.

## Change workflow (follow for every change)

1. `git pull --rebase` first: the owner sometimes edits on GitHub directly.
2. Edit, then build exactly as CI does: `JEKYLL_ENV=production bundle exec jekyll build`, then `npx purgecss -c purgecss.config.js`.
3. Check: no broken internal links in `_site`; for layout or content changes, screenshots at 390px and 1280px in light and dark mode (Playwright).
4. Commit with a short message, push to `main`, and stop if the push is rejected (pull and retry). Confirm that the "Deploy site" run for that commit succeeded and that the live page shows the change.
5. Tell the owner that GitHub Pages caches pages for up to 10 minutes (`⌘ + Shift + R`).

**Preferred blog routine (owner's choice, 2026-10-19):** when the owner supplies a paper (PDF or DOI), read it, write the post following the style guide (with code-generated original figures and scripts in `scripts/blog/`), show the full draft in the conversation, and publish it once the owner approves.

**New blog post from the owner's [POST]/[SCRIPT] blocks:** create the files exactly as given; adjust only front matter if needed (date with `+0900`; it must not be in the future at build time). Run each script from the repo root to write `assets/img/blog/`, commit scripts and PNGs together, apply the style guide above (image line, caption pattern, GitHub links to the scripts in the closing line, `post_url` for links to earlier posts), check every DOI against Crossref/doi.org and report mismatches without silently changing the owner's text. A new paper by the owner also gets a News item (see News rules above).

## How to work in this repo

- Build and check locally before pushing (see README). CI runs `bundle exec jekyll build`, then PurgeCSS, then deploys; after deploy, `broken-links-site.yml` fails on any broken **internal** link, so every local link must resolve. Links to the blog are wrapped in `{% if site.posts.size > 0 %}` while it has no posts.
- `deploy.yml` only runs when files matching its `paths` list change; `**.scss` was added (2026-10-18) after style-only pushes were silently not deployed. If you add a new kind of source file, add it there too.
- `upgrade-check.yml` runs `bundle exec al-folio upgrade audit`; keep the `al_folio` contract keys in `_config.yml` (see [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md#the-v1-config-contract)).
- `_includes/hook/bib.liquid` is a site hook that the theme's bib layout calls; it is not an override of a gem file. Prefer config, data, and page front matter (such as `_styles`) over overriding gem files.
- **Theme overrides** (acknowledged in `.al-folio-overrides.yml`; after a gem update run `bundle exec al-folio upgrade overrides audit` and re-check them):
  - `_includes/header.liquid`: the lab logo (`assets/img/logo/hydroclimate-lab.webp`, transparent WebP made from the owner's artwork, 38px high, 34px on phones, shown white in dark mode) in the top bar on every page, with `site.title` as its alt text. The favicon (`assets/img/favicon.png`) and the iOS home-screen icon (`assets/img/apple-touch-icon.png`, on white) are the ring-and-river mark the owner supplied (a closed circle, without lettering) (`icon:` and `apple_touch_icon:` in `_config.yml`).
  - `_includes/news.liquid`, `_includes/latest_posts.liquid`: full dates on one line ("Oct 20, 2026"; several items can share a month; the News page, grouped by year, shows "Oct 20"), no fixed-height scroll box, Home shows the `announcements.limit` (5) latest news items, "All news"/"All posts" links on Home. News starts in 2025: every publication from 2025 onward has a news item, and nothing dated before 2025 goes in News (owner's decision, 2026-10-18). Add an item for each new paper. News items are one-sentence, text-only `inline: true` entries; no photos (owner's decision, 2026-10-18).
  - `_layouts/bib.liquid`: on the Publications pages each title links to the paper (`https://doi.org/<doi>`, or `url` when there is no DOI; technical reports without either stay plain text), and there is no DOI button (owner's decision, 2026-10-19). Journal badges (`abbr`) are plain labels: `_data/venues.yml` was removed so they no longer link to journal home pages. News items keep their own `[DOI](...)` links.
  - `assets/css/main.scss`: the theme's entry point plus `@use "site";`, which loads `_sass/_site.scss`.
- **Accent colour (light mode):** links and other accents in USU navy `#0f2439`, turning a lighter blue `#246bac` (as on usu.edu) on hover (CSS variables and an `a:hover` rule at the top of `_sass/_site.scss`; owner's choice, 2026-10-19). Dark mode keeps the theme's cyan. Do not reintroduce the theme's purple.
- **Rules (dividers):** menu pages (page layout with a description) have a rule under the page header (except pages that open with an introductory paragraph, such as Research and Join us, where the introduction stays with the title), a rule above each section heading after the first (`h2`, also "Course content"), and rules between publication entries and table rows (Projects, News); Home has a rule above "News" and "Latest posts" (in `_pages/about.md`). Owner's request, 2026-10-20.
- **Site CSS** is in `_sass/_site.scss`: opaque top bar, hamburger menu kept up to 991px (in `@layer components`, because the theme's `!important` rule lives in that layer), phone typography (16px, line height 1.6) and spacing, a smaller back-to-top button, and blog figure/caption sizing. `#back-to-top` is created by JavaScript, so it is safelisted in `purgecss.config.js`.
- **Mobile checks:** before pushing layout changes, take Playwright screenshots at 375, 390 and 1280px in light and dark mode (the dev dependency `@playwright/test` is already in `package.json`).
- The template's sample content and the CI workflows that tested it (`unit-tests`, `visual-regression`, `prettier`, `lighthouse-badger`, `render-cv`, `update-tocs`) were removed. `test/` remains only because `package.json`/`package-lock.json` are kept as upstream so that `npm ci` works.
- GitHub Pages must serve the `gh-pages` branch (Settings → Pages), not `main`: GitHub's built-in Jekyll build cannot load the `al_folio_core` theme. The root `.nojekyll` file (listed under `include:` in `_config.yml`) is copied into the build so Pages serves it as-is. The root `CNAME` file (`hydroclimatol.com`, also under `include:`) must stay: the deploy action replaces `gh-pages` with `_site` on every run, so a CNAME that is not in `_site` would be deleted and the custom domain dropped.
- Active workflows are pinned to `runs-on: ubuntu-24.04` because `ubuntu-latest` moves to Ubuntu 26 on 2026-10-19; revisit once `ruby/setup-ruby` supports it.
- `assets/json/resume.json` is a stub kept because `jekyll_get_json` in `_config.yml` reads it.

## Gem version pins

`Gemfile` pins every `al-*` gem to an exact released version in `group :al_folio_plugins`, and `_config.yml` lists the same gems under `plugins:`. A plugin present in only one of the two is inert.
